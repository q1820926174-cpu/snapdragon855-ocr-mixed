## 混合精度设计

**v0.2 原生 GPU 路径**是用 PNNX 20261020 从原始 ONNX 单独导出的版本。CNN 使用 FP16 存储与运算，序列／分类尾部保持 FP32；不使用 INT8 模型、NPU 上下文或 SNPE。模型与哈希位于 `models/gpu-native/`，详见 [GPU 指南](gpu-native.zh-CN.md)。下述旧混合配置继续保留。

大尺寸 1×1 卷积先进行输入中心化和通道缩放平衡，再交给 NPU 执行无偏置 W8A8 计算。W8A8 表示权重和激活值均采用 8 位量化。

GPU 使用 FP32 恢复输出通道缩放与原始域偏置，并用 CSR 稀疏点积修正被裁剪的权重离群值。非线性、归一化、注意力和分类头也保留在 GPU 上。

| 配置 | 计算方式 |
|---|---|
| `quality` | 选中的前 12 个卷积交给 NPU；同一权重网格执行两次 W8A8，第二次计算放大后的输入量化残差，再由 GPU 合并。其余 GPU 算术与存储保持 FP32。 |
| `fast` | 16 个选中卷积各执行一次 NPU 计算；将 TF8/NHWC 转换与 GPU FP16 pack4 存储转换融合。 |

`quality` 的两次计算不代表硬件原生支持 W8A16。名称中的“保精度”也只描述它保住了本组测试中的 CPU 正确样本，不代表优于纯 GPU 或对任意图片无损。

## 校准与方案选择

发布的 PTQ 模型使用 20 张独立校准裁剪图，其中英文 10 张、中文 10 张。通过 raw SHA256 检查，排除了与 310 张回归图的重合。

另外尝试了 130 张独立图片的激活校准，以及 80 张训练、20 张留出的教师蒸馏微调。QAT、直接扩大 min/max 范围和加权裁剪候选，在实测回归精度上更差，因此没有进入公开默认模型。

每层公开的 `model.onnx` 将冻结的 W8 网格存储为反量化后的 FP32 常量，方便旧 SDK 导入，并附带固定量化参数。需要在本地通过 SDK 转换后才能进行物理 INT8 推理；普通 ONNX Runtime 不会因此自动启用 NPU。

## 评估边界

原生 GPU 在 310 张主集上从 256 张正确提升至 257 张，保留了旧 GPU 和 CPU 原本正确的全部整行。100 张补充校准图片保留了旧 GPU 正确的全部 87 张。主集字符编辑错误为 835/2447（旧版 836/2447），补充集为 30/651（旧版 29/651）。因此整行保留门槛通过，但**并非每个精度指标都有改善**。补充集同样有先前校准使用经历。FP32 图转换检查与 FP16 实机回归是两项不同检查，都不能证明逐位或普遍无损。

310 张图片是**开发过程中用于方案选择的固定回归集**，不是从未参与开发的独立最终测试集。

`quality` 保留了 CPU 原本正确的全部样本。`fast` 虽然最终正确数只减少了 3 个，但它实际丢失了 5 个原本正确的样本，同时改善了另外 2 个样本。详见[测试与能耗](benchmarks.zh-CN.md)。

校准图、测试图及其转录不随公开包分发；部分校准图片来源未声明图片再分发许可。公开内容为模型参数。独立验证请使用自己拥有相应使用权限的语料。

## 适用范围

本项目用于开发与测量实验。尚未针对安全关键 OCR、所有三星/SM8150 机型、主线内核、新版 HTP SDK、Android 或任意相机输入完成验证。手机桌面和远程访问服务与本仓库相互独立。
